# Prepare for an interview

## Inputs

Read [AGENTS.md](../../AGENTS.md), [interview guidance](../../guides/interviews.md), and the role files, tracker, career evidence, stories, wishlist, and prior debriefs. Use [technical practice](../../guides/technical-practice.md) only for the applicable track.

Ask for stage, date/time/timezone, duration, format, participants if known, allowed tools, invitation source, and preparation time. Don't repeat details already confirmed in the files. If key facts remain unknown, proceed with a provisional brief and list them.

## Tailoring procedure

1. Separate the confirmed format from guesses. Research company/product context and public professional background only when it helps. Record sources and dates, don't infer personality or a private evaluation rubric.
2. Identify what this stage needs to establish and what the candidate wants to learn. Use previous debriefs without treating speculation as employer feedback. Select the appropriate recruiter, manager, behavioral, coding, design, product, portfolio, data, leadership, or final-round track.
3. Select a natural introduction and two or three confirmed stories. Map each to a likely need, personal ownership, a decision, result, and limitation. Ask for missing evidence rather than filling gaps with an ideal answer.
4. Build a short question list that could change the candidate's decision. Prioritize scope, support, work, expectations, constraints, and relevant compensation mechanics. Avoid questions already answered unless clarifying a conflict.
5. Tailor practice to the role and available time. Choose one core exercise, one requirement-change variation, and one observed skill gap. Give concrete completion criteria or a learning goal. Mark invented prompts as original practice, not actual employer questions.
6. For a project deep dive or portfolio presentation, follow the guide's deep-dive section and use [deep-dive.md](../../templates/deep-dive.md). Help choose a project with a clear user problem and supportable outcome, build the narrative with the candidate's contribution separated from others', label every number as measured, estimated, reported by users, or single case, and prepare speaker notes, a timer, a cut plan, and a static or PDF backup. Rehearse with follow-up questions. Run a confidentiality review before any copy is shared.
7. For assessments, review rules and prep logistics only. Executing or solving the real assessment needs a separate explicit request and policy check. For live interviews, unknown AI permission is not authorization to assist during the event.
8. Save [interview.md](../../templates/interview.md) under `applications/<company>/<role>/` as `prep-<stage>-<date>.md` or update an existing clear prep file. If the role isn't established, use `role-unconfirmed` as the directory instead of guessing a title or placing the brief directly under the company. Keep the quick brief first, deeper reference material after it. Use [system-design.md](../../templates/system-design.md) only when appropriate and only share through an approved destination.

## Completion

Return the brief path, highest-priority practice, known gaps, logistics still to confirm, and sources not reverified. Offer a mock session without starting it automatically. Don't mark the interview completed or claim a guessed question is likely based on nonexistent evidence.

## Session checkpoint

Before stopping or changing workflows, save the canonical files and update `session.md` under the selected private workspace using the checkpoint contract in `AGENTS.md`. Record the pending candidate decision and checks actually performed. Honor declined storage, and don't mark a task complete merely because a draft exists.
