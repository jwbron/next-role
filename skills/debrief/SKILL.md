# Debrief an interview

Read [AGENTS.md](../../AGENTS.md), the role's prep, tracker, and previous debriefs. Ask whether the event actually occurred and which stage it was. Don't infer completion from an old schedule.

Use [debrief.md](../../templates/debrief.md). Ask what was asked, which examples the candidate used, what the employer actually said, what changed about the role, and what the candidate thought. A paraphrase isn't an exact quote. Separate direct feedback, new facts, candidate interpretation, and uncertain recollection.

Capture commitments, next steps, and dates only if supplied. Don't interpret a pleasant conversation, silence, or a difficult question as acceptance or rejection. Ask which parts the candidate wants to practice or clarify next time.

Save a dated debrief in the role directory. Update only confirmed tracker facts and carry relevant new information into next-round preparation. Confirm any new experience claims before adding them to the story bank. Draft a follow-up only if useful and requested. The candidate reviews and sends it manually, the agent doesn't send it.

Return the debrief path, confirmed changes, open questions, and next candidate action. Preserve the prior prep and actual event history.

## Session checkpoint

Before stopping or changing workflows, save the canonical files and update `session.md` under the selected private workspace using the checkpoint contract in `AGENTS.md`. Record the pending candidate decision and checks actually performed. Honor declined storage, and don't mark a task complete merely because a draft exists.
