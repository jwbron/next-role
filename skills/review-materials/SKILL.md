# Review materials

Read [AGENTS.md](../../AGENTS.md), [answers](../../guides/answers.md), [material formats](../../guides/material-format.md), and the selected packet, profile facts, voice, and tracker. Confirm the scope, review-only is the default. No review subagents are required.

Check in this order:

1. Facts and attribution: trace important claims to candidate-confirmed evidence. Distinguish missing evidence from falsehood. A posting doesn't establish candidate experience. Protect confidential details.
2. Policy and form: verify the exact role's questions, limits, initial-draft rules, disclosures, and tool restrictions. State what was not rechecked. Don't substitute another company's policy.
3. Usefulness: does the resume show relevant work, does the letter add a real reason, and do answers address their prompts? Don't enforce an arbitrary essay length or unsupported screening score.
4. Voice and separation: preserve candidate wording where it works. Keep private notes, thresholds, legal placeholders, and unrelated interview processes out of submission text.
5. Consistency: confirm the current attachment paths, mirrored answers, and status. Run the validator when dependencies are available. Inspect intentional layout changes or state that visual review is pending. Don't rebuild existing attachments merely to audit them.
6. History: prepared doesn't mean submitted, and current files don't identify what was sent. Preserve submitted snapshots and request old receipts only if they matter.

Agent review does not replace manual candidate review of the exact material. Check whether the candidate has reviewed the current version, not just its source facts or a prior draft. Identify what still needs their factual judgment, policy check, or visual inspection. Don't infer approval from silence or successful mechanical checks. Substantive edits require renewed review.

Return concrete findings with file paths, supporting evidence, priority, and suggested corrections. Separate factual problems from optional style suggestions. State mechanical, visual, policy, and availability checks independently. If authorized to fix, edit only the agreed scope and rerun relevant checks. Never submit as part of review.

## Session checkpoint

Before stopping or changing workflows, save the canonical files and update `session.md` under the selected private workspace using the checkpoint contract in `AGENTS.md`. Record the pending candidate decision and checks actually performed. Honor declined storage, and don't mark a task complete merely because a draft exists.
