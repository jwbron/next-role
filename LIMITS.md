# Scope and limits

next-role prepares materials and decisions with a candidate. It doesn't apply, message, publish, or decide for them. These limits apply to every workspace built from it.

## What the checks cover

- Automated tests use fictional, temporary workspaces. They cover initialization, PDF rendering and text parity, configurable page limits and paper size, Unicode fonts, overwrite protection, required disclosures, stale attachments, answer limits, path boundaries, public resume variants, and the starter file inventory.
- [Agent scenarios](tests/agent-scenarios.md) describe how a fresh agent session should behave in onboarding, resuming, restricted policies, failed writes, automated-application requests, publishing, and postings that address AI tools. They're checks to run, not guarantees that every agent follows every instruction.
- Mechanical checks don't establish factual accuracy, employer-policy compliance, voice, visual quality, live availability, or application status.

## Product limits

- The reusable starter uses the [MIT License](LICENSE). Review rights and confidentiality separately for material imported into a private workspace.
- These files don't create repositories, push, publish, or deploy anything.
- Interview practice and market data need role-specific research at use time. No live listings or salary tables ship as current recommendations.
- The PDF renderer isn't a general document editor. Complex scripts, right-to-left layout, accessibility tagging, and every operating system still need validation.
- Candidate file import is conversational and manual. There's no OCR, LinkedIn login, portfolio scraper, or mailbox integration.
- Backups, encryption, and assistant-provider data policies remain the user's responsibility. Ignore rules and the starter check don't guarantee privacy.
- Resume truth, form compliance, employer restrictions, negotiation arithmetic, and layout require human review.
- Academic CVs, government applications, and region-specific legal fields need their own templates and validation.
